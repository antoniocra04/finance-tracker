# Свод

Личный трекер капитала. Счета в разных валютах, датированные остатки, история, аналитика, пароль. Self-hosted на Raspberry Pi, Node.js 24 + SQLite, без npm-зависимостей и frontend-сборки.

## Возможности

- Счета: банк, название, тип, валюта. Обновление полного остатка с датой и заметкой.
- Каталог мировых валют; USD, RUB, KZT первыми в списке. Смена основной валюты без изменения исходных сумм.
- Ежедневные курсы и автоматическая переоценка, даже когда браузер закрыт.
- Капитал, валютная структура, график за месяц / квартал / полгода / год. Отдельно изменение остатков и влияние курсов.
- Журнал всех обновлений, архив счетов, JSON и CSV, полноценные резервные копии SQLite.
- Один владелец, пароль от 12 символов, scrypt, серверные сессии, ограничение попыток входа, защита от запросов с другого сайта.
- Адаптивный интерфейс, клавиатурная навигация, скрытие сумм.

## Локальный запуск

Нужен Node.js 24+. Устанавливать npm-пакеты не требуется.

```sh
npm start
```

Открыть http://127.0.0.1:3000. При первом старте терминал напечатает `Код первой установки`. Ввести этот код и задать собственный пароль. Код не отдаётся браузеру и после установки больше не используется. База: `data/svod.sqlite`.

Node.js 24.8 может печатать ExperimentalWarning для встроенного SQLite; это предупреждение runtime, а не ошибка приложения. Более свежие Node.js 24 имеют более зрелый статус модуля.

## Raspberry Pi / Docker

Нужны Raspberry Pi с 64-битной ОС (ARM64), Docker Engine и Compose. Перенесите папку проекта на Pi.

```sh
cp .env.example .env
mkdir -p backups
sudo chown 1000:1000 backups
chmod 700 backups
docker compose up -d --build
docker compose logs svod
```

Образ `node:24-bookworm-slim` поддерживает ARM64. Контейнер работает от пользователя `node` (UID 1000), данные в named volume `svod-data`. Файловая система контейнера read-only, запись разрешена только для данных, копий и /tmp. Удаление контейнера не удаляет базу; `docker compose down -v` удалит volume с данными — не используйте эту команду для обновления.

По умолчанию порт доступен только на самой Pi. Можно использовать SSH-туннель:

```sh
ssh -L 3000:127.0.0.1:3000 pi@raspberrypi.local
```

Затем открыть http://127.0.0.1:3000 на компьютере. Для доступа напрямую внутри домашней сети изменить `.env`: `BIND_ADDRESS=0.0.0.0`, применить `docker compose up -d`, открыть `http://IP-АДРЕС-PI:3000`.

### HTTPS и удалённый доступ

Для удалённого доступа используйте VPN (например, Tailscale) или HTTPS reverse proxy. Пароль защищает вход, но HTTP не шифрует трафик. Не публикуйте HTTP-порт в интернет.

Пример Caddy, установленного на той же Pi:

```caddy
money.example.com {
  reverse_proxy 127.0.0.1:3000
}
```

В `.env` установить:

```dotenv
BIND_ADDRESS=127.0.0.1
SECURE_COOKIE=true
APP_ORIGIN=https://money.example.com
```

`APP_ORIGIN` без завершающего `/`, ровно как адрес в браузере. После изменения — `docker compose up -d`. Secure-cookie работает только через HTTPS; на HTTP вход с этой настройкой не сохранится. Reverse proxy должен передавать исходный `Host`. Данные SQLite и экспорты не зашифрованы на диске: используйте защищённый диск и храните копии в безопасном месте.

## Курсы и история

Источник: [ExchangeRate-API Open Access](https://www.exchangerate-api.com/docs/free), без API-ключа. На момент проверки доступны 166 валют, включая USD/RUB/KZT. Провайдер публикует курсы раз в сутки; сервер проверяет необходимость обновления каждый час, использует время следующей публикации и кеширует результат в SQLite. При сбое повторяет через час, сохраняя прошлый курс. Дата курса видна; после 48 часов появляется предупреждение. Обязательная ссылка на источник доступна при раскрытии даты курса в верхней панели и настройках.

Курсы ориентировочные: оценка капитала отличается от банковской цены покупки/продажи. Валюту без доступного курса можно хранить на счёте, но приложение явно покажет неполный итог. Криптовалюты и котировки ценных бумаг не входят в эту версию; инвестиционный счёт хранит вручную введённую оценку в денежной валюте.

Для каждой даты берём последний введённый остаток на эту дату и последний известный на эту дату курс. До первой сохранённой котировки конвертированная история не строится: сегодняшние курсы не подставляются задним числом. Если Pi была выключена, между сохранёнными котировками переносится последняя известная оценка; пропущенные рыночные котировки не скачиваются задним числом. Балансы можно вводить задним числом, тогда график пересчитается. Новая запись за ту же дату становится закрывающим остатком; прежняя остаётся в журнале. Архив исключает счёт из капитала со дня архивации, сохраняя прошлые даты.

Суммы хранятся целым числом минимальных денежных единиц: 2 знака для USD/RUB/KZT, 0 для JPY, 3 для KWD. Максимум — 10¹⁴ минимальных единиц на один остаток. Отрицательные остатки не поддерживаются: это трекер активов, не долгов. Расчёт конвертации использует IEEE-754; округление выполняется только при отображении.

Изменение остатков = текущие остатки в курсах начала наблюдаемого периода минус начальная стоимость. Влияние курсов = текущая стоимость минус текущие остатки в начальных курсах. Это изменение стоимости, не доходность: пополнение, снятие и архивация влияют на первый показатель. Если начальных курсов не хватает, разложение не показывается. График хранит и показывает до года ежедневных точек, исходный журнал и котировки сохраняются полностью. Переключатель периода меняет только график; период итогового изменения подписан отдельно.

## Экспорт и резервные копии

В настройках: JSON со всеми счетами (включая архив), балансами и курсами; CSV со всеми записями. JSON использует поле `amount` в минимальных денежных единицах; CSV — обычные суммы. Пароли и сессии в экспорты не входят. JSON — выгрузка для анализа, автоматического импорта в этой версии нет.

Полная согласованная копия SQLite, в том числе при работающем сервере:

```sh
npm run backup
docker compose exec svod node scripts/backup.mjs
```

В Docker файлы появятся в `./backups` на хосте. Они включают хеш пароля и активные сессии. Не копируйте только основной `.sqlite` у работающего процесса: свежие изменения могут находиться в WAL. Переносите копии на другой диск регулярно.

### Восстановление Docker

Сначала остановите приложение. Файл копии разместите в `./backups/restore.sqlite`. Существующую базу сохраните отдельной копией перед заменой.

```sh
docker compose stop svod
docker compose run --rm --no-deps svod node scripts/backup.mjs /app/backups/before-restore.sqlite
docker compose run --rm --no-deps svod node scripts/restore.mjs /app/backups/restore.sqlite
docker compose up -d
```

Восстановление заменяет текущую базу и очищает сессии. Локальный вариант: остановить `npm start`, `npm run backup`, затем `node scripts/restore.mjs backups/restore.sqlite` и снова `npm start`. Пароль останется тем, что был в копии.

## Проверка

```sh
npm test
npm run check
```

Тесты запускают настоящий HTTP-сервер на случайном loopback-порту, используют SQLite в памяти; интернет не требуется. Проверяются расчёты, точность валют, архив/история, пропущенные курсы, setup, сессии, пароль, origin, невалидные данные, экспорт и сбой провайдера.
