# Interface review, 24 October 2026

Reviewed the running application in a real browser using isolated fictional accounts. No Raspberry Pi balances, password, database or settings were accessed or modified.

## Findings and fixes

| Observed defect | Fix |
| --- | --- |
| Search icon center was 8.5px above the input center | Center the icon against the control; remove toolbar input margins |
| Mobile selects used 11.76px text and compressed currency names into 152px | 16px mobile controls, full-width currency/type fields |
| Native select arrows crowded the text | Shared trailing padding and consistent caret; retain native selection |
| Sorting control truncated the longest option | Wider control, stacked toolbar at 320px |
| Account actions measured 29×30 and 28×34px | 44×44px touch targets |
| Account names and financial details were squeezed into tiny mobile columns | Full names, larger type, balance on a second row |
| Long add-account forms pushed Save beyond the visible area | Scrollable dialog body with fixed heading/footer |
| Moving submit controls could disconnect them from their forms | Explicit native form associations and event.submitter |
| A server error could remain below the visible dialog body | Scroll error into view with clearance above the footer |
| Busy copy could change button height and move the footer | Preserve the original label's geometry while displaying pending text |
| Icon-only tablet navigation and logout lost accessible names | Explicit accessible labels |
| Mobile navigation hid the only logout control | Logout in settings |
| Currency changes left the amount hint in the old precision | Update amount label and hint; JPY 0 decimals, KWD 3 |
| Rerender could move keyboard focus to the first account action | Restore focus by action and account id; keep period/privacy focus |
| Empty counts read «0 счёта» / «0 валюты» | Shared Russian plural rules |
| Old success messages could remain on the login screen | Clear transient notifications on auth rendering |

## Verification

- All five sections tested at 320, 390, 768, 1024 and 1280px: 25 combinations, no horizontal page overflow or unnamed visible buttons.
- Desktop and mobile screenshots inspected: accounts, settings, journal, add-account dialog and error state.
- A JPY account was created through the pinned footer; the amount hint changed to `0`.
- Invalid JPY precision produced a fully visible error while the action footer remained inside the viewport at 320×740.
- Updating a non-first account returned focus to that same account's update button.
- Mobile logout opened the password screen successfully.
- Existing 10 automated tests, JavaScript syntax checks, and Git whitespace checks pass.
- Browser viewport emulation was used for phone/tablet widths. Physical mobile devices and the remote Raspberry Pi deployment were not directly tested.
